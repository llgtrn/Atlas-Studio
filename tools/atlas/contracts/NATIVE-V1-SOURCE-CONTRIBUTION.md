## Authority and scope

Provenance: the explicit owner decision supplied for this campaign at **2026-10-16
16:43:08 UTC**, titled **OWNER DECISION — FULL V1 NATIVE OPERATING ORGANISM. NO SCOPE
REDUCTION.** This document applies that decision to Atlas source contribution guidance.
It does not mint a concept, change a stable identity, select an implementation directory or
replace the central [Blueprint](https://github.com/llgtrn/.Ynventa-/blob/main/BLUEPRINT-V1.md).
The engine lane owns publication of the detailed **Native OS V1 Completion Contract**;
that publication and its immutable pin are pending. The Blueprint link is a mutable locator,
not a claim that the pending contract is already present there.

**Required final product:** one graph-native Chronica Digital Intelligence Holobiont Operating
System, capable of independent native operation on one certified hardware target, with
Norl/Neurora cognition, homeostatic regulation, governed technology assimilation, continuity,
and governed reproduction of offspring sharing one canonical World.

Linux is for development, bootstrap and testing. The final V1 must not require Linux or Windows
as its kernel/runtime. A userspace application, daemon, container, hosted inference demo, glossary
or software-test count is not native OS completion. All nine journeys below and all P0–P3 work
remain V1 obligations; phases order dependencies, not scope reduction or deferral to V2.

This campaign is documentation first. Held implementation patches, staged files and old evidence
remain separate; this guidance authorizes no feature work, engine/schema change, credentials,
hardware/compute purchase or change to the user's computer. Product UI ownership remains
exclusively Chronica; Atlas source UI stays frozen until real, verified consumer cutover.

A device is a hardware endpoint, a replica carries/replays authorized state, a worker performs
bounded work, and an offspring is a governed distinct organism. These roles must be distinguished
in the detailed contract; the distinction here introduces no new wire type or identity schema.
Inheritance, local cognition, offline limits, network partitions, reconnection and reconciliation
remain required engineering work. The settled same-World offspring decision is not reopened.

## All nine V1 product journeys

Every row is a **required target acceptance**, not a result obtained here. The central contract
must connect these journeys to the owner/I/O/state/authority/failure obligations above and to one
feasible selected hardware profile; certification is blocked until that profile and tests exist.

| Journey | Required acceptance chain / current gap |
|---|---|
| 1. Boot-to-Intelligence | Power on supported hardware → verified native startup → restore identity/World → real-weight Norl inference; no complete native chain established here |
| 2. Organism Continuity | Crash, power loss and replay preserve identity, durable work and canonical history; target recovery qualification remains open |
| 3. Owner Founding and Rescue | Establish ownership and recover through a deterministic native interface with inference unavailable; no invented recovery rights |
| 4. Privacy and Forgetting | Exercise authorized disclosure/forgetting with explicit evidence-retention and recovery behavior; full target policy/caller qualification remains open |
| 5. Living Evolution | Admit assimilation/training/migration/activation separately, retain competence and survive interrupted transitions; source tests alone do not establish this |
| 6. Multi-device and Genesia | Distinguish devices, replicas, workers and offspring; prove bounded reproduction, offline authority and same-World reconciliation |
| 7. Usable Workspace | A user interacts natively and performs governed work, with basic diagnostics/rescue available without cognition; Atlas's placeholder Studio is not this workspace |
| 8. Continuous Extinction Closure | Verify native replacement, parity, dependency closure, caller cutover, rights, retained competence and current evidence before extinction |
| 9. Native Operating Envelope | Demonstrate kernel/runtime, required drivers, resource regulation, isolation, durability, updates and recovery under measured hardware limits; hosted Linux success is insufficient |

The final witness must show the complete sequence on the certified target: power on → Chronica
OS boots → identity/World restored → real-weight inference → user interaction and governed work →
homeostasis, fault handling and recovery → authorized Genesia offspring operation in the same
canonical World. If the sequence is unproven, **V1 is not complete**, regardless of terminology
coverage, hosted tests, partial kernels or phase labels.

Technology reuse remains possible. Driver, bootloader and algorithm research need not start from
zero, but each adopted technology must satisfy native closure, parity, rights, caller and current
evidence gates. No kernel architecture, hardware model, accelerator stack or inference model is
selected by this guide. Native architecture comparisons and the one-target completion contract
belong to the coordinated central documentation lane; their publication is still pending.
