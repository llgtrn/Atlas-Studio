# Atlas Development Guide

Before coding, read the North Star, Genome contract, universal graph contract, format contracts, system blueprint/roadmap and resolve the exact base SHA.

## Work sequence

1. Resolve exact target repository and revision.
2. Load and pin the Atlas Genome identity.
3. Determine affected scope from federation/repository down to semantic atoms.
4. Admit source, donor and research evidence with provenance.
5. Census code reality before proposing implementation.
6. Correlate DeepWiki/docs/papers/specs without confusing explanation with current code reality.
7. Update or synthesize the engineering graph and selected design.
8. Publish/update the target `*.atlas` artifact when the binary pipeline exists; before then, implement the same semantics in typed runtime structures and evidence.
9. Materialize deterministic `*.atlasx/`.
10. Compile with the active compiler phase.
11. Test, benchmark where material, and recensus generated implementation.
12. Compare intended graph with observed implementation.
13. Record evidence and only then extinguish absorbed donor runtime dependency/scope.

## Current bootstrap language policy

Backend/compiler/runtime implementation is Rust. Frontend is TypeScript/TSX. C is only an explicit low-level/FFI/device/vendor boundary unless an approved target contract says otherwise.

Do not mechanically translate donor source from C/Go/Python/etc. to Rust. Census mechanisms and invariants first, then synthesize Atlas-native design, then materialize Rust.

## Cross-repository rule

A work run may mutate one canonical target repository at a time, but analysis may span the federated graph. If a change requires multiple repos, split mutation into exact-revision repo-local runs joined by explicit cross-repository bindings/evidence.

Every new repo generated by Atlas must satisfy the universal graph boundary contract so later repos can connect without semantic archaeology.

## Documentation and generated state

Durable architecture/contracts/genome source live under `.atlas/`. Rebuildable reports/caches live in `.atlas/.cache/`. Human-readable Atlas/AtlasX exports are projections, not canonical binary semantics.
