# ADR 0091 — Imports settle as rustc binds them (G178)

## Context

G178 is replay R15 of `egraphs-good/egglog`, pinned at `90635860` (upstream master, and also the G82 decision pin). The e-graph engine had been REVALIDATION_REQUIRED since G150, at rank 3.

**The falsification.** At E23 the import fixed point over egglog's workspace never settled within 64 rounds. The fallback opened every module of every crate, and 102 components withheld 2,310 path calls; 1,289 of them named "imports reach no fixed point" as their cause. The resolver iterates the workspace as one state, so one crate that never settles opens all of them.

Two independent causes kept it moving:
- **A period-4 oscillation.** `src/ast/mod.rs` holds `use crate::*;` and then `pub use expr::*;`. Both bring the same items. `Scope::insert` kept the visibility of the binding applied first, so the re-export was private when the root already held the name and public when it did not. Each hop between the two modules takes a round, so the state returned every fourth round. The G162 merge (ADR 0077) recognizes only period 2.
- **A path that grows every round.** `use quote::quote;` looked its first segment up through its own binding. Since G177 a registry binding keeps its path, so the path gained a segment each round and the state never repeated. The older `use alloc::alloc;` grew a standard path the same way, and the fallback, which still trusted named imports, claimed it: `external:alloc::alloc::alloc::…::Layout::new`.

Once the fixed point settled, the replay exposed a WRONG claim the open scopes had hidden. An `extern crate` item was always bound to an external root. egglog's root declares `extern crate self as egglog;`, and `src/prelude.rs` reads `use crate::*; pub use egglog::{EGraph, ..};`, so calls of the crate's own `EGraph::default` were claimed external. G177's rule (ADR 0090, item 7) covered only the extern prelude, which a lexical lookup never reaches when the item itself is in scope.

## Decision

1. **Two bindings of one item keep the wider visibility.** When two bindings of the same origin and definition meet in a scope, the more visible one stands, whatever the order they arrive in. This is rustc's `try_define`. The two always compare: an import's visibility is public, its crate, or a module enclosing the importer.
2. **An import never reads its own binding.** An import that binds the name its path starts with resolves that first segment with itself ignored (rustc's `ignore_import`): the scope's item of that name, then its other named imports of that name, then its globs, then the outer scopes, then the extern prelude. Another self-named import of the same name makes it Unknown (rustc: "cannot determine resolution for the import"). Only the one name is looked up, so the cost is linear in the module's imports.
3. **Without a fixed point, nothing imported is trusted.** The 64-round fallback makes every non-item entry Unknown, named imports included, as its comment already said.
4. **An `extern crate` item names its crate.** Every module's `extern crate x [as n];` items are recorded and, once all crates are collected, bound to the crate they name: `self` to the crate root, a workspace crate to its root, anything else to an external root. One under `cfg`, one carrying a possibly procedural attribute, or two of one name are Unknown. The crate root's items feed the extern prelude through the same function, so the item and the prelude always agree.
5. **An external import may bind nothing in a namespace.** Atlas cannot see whether an external item is a type, a value or both, and rustc binds an import only in the namespaces where its target exists. A named import of an external item is therefore marked unsure. A lookup that finds it also looks past it, to outer block scopes and, for a path's first segment, to the extern-prelude crates Atlas knows (`std`, `core`, `proc_macro`, crate-root `extern crate`s, workspace crates, lock-confirmed registry dependencies). The two answers combine:
   - the same definition: that definition;
   - two external items: external, with the path kept only where both agree, otherwise external with no path;
   - anything else: Unknown.

   So `use alloc::alloc::{alloc, dealloc, Layout};` no longer roots later `alloc::` paths at the function. A small table of standard items named like a standard crate (`alloc::alloc`, `core::alloc`, `std::alloc` are modules only; `alloc::alloc::alloc`, `std::alloc::alloc` are functions only) binds those in their one namespace.
   - **Every declared dependency name counts.** Besides the crates Atlas can read, every name the manifest declares for the target (registry, git, path or workspace, confirmed by the lockfile or not; `-` read as `_`; a workspace library's own name; a binary's own package library) is an extern-prelude crate of unknown contents. Beside one of them an unsure import is withheld. `use std::iter::zip;` next to a git `zip` dependency no longer claims `zip::open` as `std::iter::zip::open`, nor a workspace method where `zip::Ext` supplies it.
   - **Order never matters.** A binding merged from unsure named imports and globs keeps both sides; a later glob joins the glob side, a later named import the named side, and the merge is recomputed, so the answer depends only on the two sets.
6. **A glob re-export is no wider than what it reads.** A glob entry's visibility is the narrower of the import's and the entry's; an enum-variant glob takes the enum's.
7. **A dependency is known by the name Cargo passes.** An unrenamed dependency on a workspace library, and a binary's own library, enter the extern prelude under the library's crate name (`[lib] name`, `-` read as `_`), not the manifest key or the package name. Any `package` field, even one repeating the key, makes the key the name. The manifest is read by a small native TOML reader instead of a line splitter. It reads every string kind (multi-line included), escapes, arrays and inline tables across lines, and places each value at its full key path, so `[dependencies] x = ..`, `[dependencies.x]`, a dotted `dependencies.x = ..` before any header and `[target.'cfg(..)']` with `dependencies.x = ..` are one entry; a leading byte-order mark is dropped. An entry it cannot read with certainty -- an unreadable value, a key given twice, a nested table, a `path` or `package` that is not a string -- is declared (it withholds) but binds nothing; so does an empty path, an inherited entry whose workspace root is not in view, and two entries that would pass one name for different libraries. A dependency the old reader dropped was read as absent, and an import beside it trusted.
8. **`pub(in path)` is the module its path names.** The path (`crate`, `self`, `super`, or the 2015 crate-root form) is walked along the item's ancestor modules. A path naming no ancestor leaves the item private to its own module, never crate-wide.

## Evidence

- **egglog at `90635860`,** the E23 resolver and this one over the same pin:
  - INVOKES 1,586 -> 1,812, none lost. Withheld path calls 2,310 -> 1,497; open-scope components 102 -> 59.
  - Function level, against rust-analyzer 1.90.0's SCIP index of the eight crates (sysroot_src loaded): 1,491 -> 1,703 edges, 1,490 -> 1,702 agreed, recall 27.99% -> 31.97%. The one edge only Atlas holds sits under `cfg(feature = "bin")`, which the index does not see, and reads correct.
  - Call sites: 250 newly resolved, 244 confirmed by the index. Four sit under doc comments longer than the checker's 40-line window and name the same `fn`; two sit in `cli.rs` tests under `cfg(feature = "bin")`. All six read correct.
  - 417 calls become external paths; 322 are confirmed external by the index, the rest are the trait-path convention (`Default::default` names core's trait method; the index names the impl) or standard calls where the index records a workspace symbol among the arguments.
  - 13 external claims withdrawn: 11 standard calls whose modules the settled fixed point leaves open (withheld, not retargeted), and two `GenericActions` calls wrongly claimed external before this change.
  - The planner question `tree_decompose_and_plan -> decompose_into_bags` goes from NO_PATH_OBSERVED (UNKNOWN, 19 unresolved call sites at the origin) to one INVOKES step.
- **Atlas itself:** the E23 binary and this one produce byte-identical models of the same tree. Every registry dependency of Atlas is locked, it has no git dependency and no `extern crate`, and its import graph already converged.
- **Rust facts checked with rustc 1.90.0** (editions 2015 to 2024 where they differ): glob re-exports of one item at two visibilities in both orders; `use alloc::alloc;`, `use x::f as x;` through another import and through a glob; `use core::a as alloc; use alloc::b as core;` refused; `extern crate self as n;` in the root and a submodule, globbed and re-exported; `extern crate b as other;` for a workspace crate; an import naming a function beside a same-named crate; `pub(in path)` along ancestors and refused beyond them; glob re-exports of a `pub(super)` item and of restricted enum variants; a value-only std import beside a git dependency of the same name.
- **Review.** Two independent adversarial passes and a confirmation:
  - **First pass, four holes:** an external import bound in both namespaces rooted `alloc::` paths at `alloc::alloc::alloc` (a WRONG claim); the self-excluding lookup re-applied every glob per own-named import (57x slower at 500 imports); a glob re-export kept the import's visibility instead of the narrower one; `pub(in path)` was read as crate-wide. The last two are older than this change, but the kept-wider rule relies on them.
  - **Second pass, two more:** a value-only std import beside a dependency the lockfile does not confirm still claimed the std path and a workspace method edge (older than this change); and the merge of an unsure import with globs depended on application order. The timing test's margin was widened to 8x on the best of three runs (a regression runs at 30-39x).
  - **Third pass (confirmation),** closing both: an older WRONG claim, workspace dependencies keyed by manifest key instead of library name (`core = { path = .. }` naming a library `kernel` made `core::mem::swap` the workspace function), and manifest headers with a trailing comment, spaces or quoted keys dropping their dependencies, which re-opened the second pass's hole.
  - **Fourth pass (confirmation of the manifest reader),** by differential against Python's `tomllib` over the 636 registry manifests on the machine and generated corpora: the line splitter read a triple-quoted `path` as empty, binding a dependency to the package's own library (a WRONG binding the third pass's fix introduced), and, older, took a table header written inside a multi-line string as a real table, counted braces inside strings, dropped dotted dependency keys at the root or under a target header, missed the first header after a byte-order mark, and bound an inherited dependency by package name when the workspace root was not in view. The reader was replaced; the same differential then found 0 wrong, dropped or extra entries over 636 registry manifests, Atlas's 10 and 12,088 generated ones (triple-quoted strings holding headers, braces and `#`, dotted keys, byte-order marks, CRLF, `\x`/`\e` escapes, Cargo-invalid values), and 4,001 mutated or deeply nested files raised no panic.
  The review found sound the visibility chain `covers` compares, rustc's uniform-path ambiguity (E0659) cases, glob-shadowing priority, determinism (ordered maps only), termination, the std-path tables' exact matching, the standard items named like a standard crate, and the restricted-visibility forms.
- **Tests:** in `resolve/tests.rs`, `one_item_through_two_globs_keeps_the_wider_visibility`, `an_import_never_resolves_its_path_through_its_own_binding`, `without_a_fixed_point_no_named_import_is_trusted`, `an_extern_crate_item_binds_the_crate_it_names`, one test per review hole (external namespaces, own-named cost, glob visibility, restricted visibility, declared dependencies, merge order); in `resolution/tests.rs`, `every_declared_dependency_names_the_extern_prelude_whatever_its_source`.
- **Mutants: 88 killed,** each applied alone and restored byte-identical: 16 on the convergence rules, 9 on the `extern crate` binding, 16 on the first review's fixes, 11 on the second's, 12 on the third's, 24 on the fourth's. Two survived their first run -- a merge mutant until the order test gained a one-item case, a body-comment mutant until the manifest test gained a comment holding a comma -- and were then killed.

## Consequences

- **DEBT-CALL:** the import fixed point converges wherever rustc's does, and a scope is opened only for an unseen expansion, never for non-convergence of Atlas's own model. Capability epoch E24. It fires no processed replay's trigger.
- **Still withheld (recorded, not wrong):**
  - `self::`-prefixed imports that would read another import of their own name;
  - `#[cfg_attr(.., macro_use)] extern crate`, and an un-renamed `extern crate` under `cfg`;
  - a certain named import and an unsure one of the same name give the correct claim or a withhold depending on their order (never a wrong claim);
  - an unrenamed registry or git dependency whose `[lib] name` differs from its key, and crates passed by `--extern` outside Cargo, are read as absent;
  - a non-converging input still opens every module of the workspace; bounding the fallback to one crate needs per-component settling;
  - `workspace = true` beside a `path` is withheld (Cargo ignores the path); the dependency census's consumer names and the registry `[lib] name` reading of `locked_traits` still read lines (Cargo normalizes registry manifests).
- **Queued:** NA-EDITION-2015. Paths in 2015-edition crates are crate-relative; Atlas reads them as 2018 paths and leaves them unresolved.
